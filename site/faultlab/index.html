FaultLab

Bounded fault experiments against the lab gateway, journaled so a run can be audited afterwards: intent before mutation, cleanup on a fresh bounded context, TTL expiry enforced by the gateway itself.

recorded live run Read-only dumps of the SQLite journals committed under results/faultlab/. Timestamps and states are exactly as the runner wrote them on the dates shown — nothing is replayed or edited.

What each state means

statemeaning
PREFLIGHTcontext checked, injector reachable, no mutation yet
BASELINE → OBSERVINGunfaulted load, then fault applied and observed
CLEANINGrecorded faults cleared, zero live faults verified
VERIFYINGpost-cleanup health, workload validity, declared assertions
PASSED / FAILEDterminal outcomes
CLEANUP_FAILEDrestoration could not be verified — never a success

Schema note

The journals above were recorded on 2026-09-28. Since the 2026-10-05 correctness work the runner additionally journals cleanup-ok, recovery-health, recovery-failed, recovery-skipped, phase-load and oracle, persists every workload phase to phases.json, and refuses to report PASSED unless the post-cleanup recovery phase met its health gate. Those paths are unit-tested (-race green); a live rerun with them is still pending, so no new live claim is made here.
